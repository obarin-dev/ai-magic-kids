# sketch-animator

娘の描いた絵に、AIで骨格（いのち）を吹き込むプロジェクト

## 1. コンセプト

「AIをただの全自動ツールにしない。」  
Gemini 1.5 Flash のマルチモーダル機能を活用し、画像から骨格データを抽出。  
そのデータを子どもが **プログラミング的思考（ブロック命令）** で自由に操作できる、親子共同開発アプリです。

## 2. 背景と想い

### 規約への対応

低学年の子どもが直接 AI API を叩くことは規約上制限されるため、以下の分担で設計します。

- 親: エンジンの設計（API管理）
- 子ども: 操縦（アクション設計）

### 知育の視点

「AI が勝手にアニメーションを作る」のではなく、  
「AI が抽出した座標を、どう動かすか」を子どもが考える体験を重視します。

- 算数（座標）の理解
- 論理的思考の育成
- 創作の達成感

## 3. システムアーキテクチャ

- **Input**: スマートフォンで撮影したアナログのイラスト（PNG/JPG）
- **Brain**: Gemini 1.5 Flash API  
  画像から主要な関節（頭、肩、ひじ、手、腰、ひざ、足）の座標を特定
- **Output**: Pygame による動的キャンバス  
  抽出したスケルトンを元に、パーツごとの移動・回転を計算

## 4. 実装予定の機能

- [ ] スキャン（アップロード）: 画像を選択し、AI に解析させる
- [ ] スケルトン・プレビュー: 解析された骨格を絵の上にオーバーレイ表示
- [ ] コマンド・ブロック: 「あるく」「ジャンプ」「まわる」などの命令ボタン
- [ ] アニメーション実行: 並べた命令に従って、Pygame 上で絵が動く

## 5. 技術的なこだわり（精通ポイント）

- **座標の正規化**: 画像サイズに依存せず、Pygame のスクリーンサイズに合わせて AI 座標をスケーリング
- **レスポンス速度**: 1.5 Pro ではなく 1.5 Flash を採用し、親子でストレスなく遊べる速さを追求
- **低環境開発**: ストレージ容量などの制約がある環境でも、クラウド API を活用して高度な推論を実現

## 6. 今後の開発メモ

- API キー管理は保護者側環境に限定する
- 子ども向け UI は「少ない文字・大きいボタン・即時反応」を優先する
- 骨格抽出結果は JSON として保存し、再利用可能にする

## 7. Web（Next.js）アップロード画面

Node.js（公式 LTS のインストーラで `node` / `npm` が使える状態）を用意したうえで:

```bash
cd /Users/nishizonoyukari/ai-magic-kids/web
npm install
npm run dev
```

ターミナルに `http://localhost:3000` と出たら、**そのターミナルは開いたまま**ブラウザで同じ URL を開いてください。`npm run dev` を止めるとページは表示されません。

表示がおかしいときは、一度 `.next` を消してから `npm run dev` をやり直してください。

```bash
cd /Users/nishizonoyukari/ai-magic-kids/web
rm -rf .next
npm run dev
```

（ファイル監視で `EMFILE` が出る環境向けに、`npm run dev` はポーリング監視を有効にしています。）
